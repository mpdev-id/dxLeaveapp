Introduction

Welcome to the DXLeave API documentation. This API provides endpoints for managing leave requests, users, and other core data for the DXLeave application.

Base URL

https://your-domain.com

Authentication

Most endpoints require authentication using a Sanctum bearer token. Include it in the `Authorization` header.

Authorization: Bearer <your_sanctum_token>

Error Responses

Errors are returned using standard HTTP status codes with a JSON body.

// Example: 422 Unprocessable Entity
{
    "message": "The given data was invalid.",
    "errors": {
        "field_name": [
            "A specific error message for this field."
        ]
    }
}

Authentication

Public endpoints for user registration, login, and password recovery.

POST/api/register

Creates a new user account.

POST/api/login

Authenticates a user and returns a Sanctum token.

POST/api/forgot-password

Sends a password reset link to the user's email.

POST/api/reset-password

Resets the user's password using the token from the email.

User Profile

Manage the authenticated user's profile.

GET/api/userAuth Required

Fetches the profile of the authenticated user.

Response (200 OK)

// Returns a User model object
{
    "id": 1,
    "name": "John Doe",
    "email": "john.doe@example.com",
    ...
}
POST/api/logoutAuth Required

Invalidates the user's current token.

Response (200 OK)

{
    "message": "Logged out successfully."
}

Leave Requests

Endpoints for employees to manage their own leave requests.

GET/api/leave-requestsAuth Required

Retrieves a list of the user's own leave requests.

Response (200 OK)

{
    "data": [
        // Array of LeaveRequest model objects
    ]
}
POST/api/leave-requestsAuth Required

Submits a new leave request (created in "Draft" status).

Request Body

{
    "leave_type_id": 1,
    "start_date": "2025-12-24",
    "end_date": "2025-12-26",
    "reason": "Christmas break"
}

Response (201 Created)

{
    "message": "Leave request created successfully in Draft status.",
    "data": { ... } // LeaveRequest model object
}
PATCH/api/leave-requests/{leaveRequest}Auth Required

Updates a `Draft` request. To submit for approval, set `current_status` to `Pending`.

Request Body

{
    "reason": "Updated reason for Christmas break",
    "current_status": "Pending"
}

Response (200 OK)

{
    "message": "Leave request status updated to Pending.",
    "data": { ... } // Updated LeaveRequest model object
}

Approvals

Endpoints for managers to approve or reject leave requests.

PATCH/api/leave-requests/{leaveRequest}/approveManager/Approver Role

Approves or rejects a pending leave request.

Request Body

{
    "action": "Approved", // or "Rejected"
    "comments": "Enjoy your time off!"
}

Response (200 OK)

{
    "message": "Leave request has been Approved.",
    "data": { ... } // Updated LeaveRequest model object
}

Admin: Dashboard

Dashboard endpoints for a high-level overview of the system.

GET/api/admin/dashboard/statsSuper Admin

Get key statistics (total users, pending requests, etc.).

GET/api/admin/dashboard/recent-activitySuper Admin

Get a feed of recent system activities.

GET/api/admin/dashboard/upcoming-leavesSuper Admin

Get a list of approved, upcoming leave requests across the organization.
