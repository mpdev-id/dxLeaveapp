API Documentation

This documentation outlines the API endpoints and usage for different user roles within the dxLeaveApp system.

Role: Member (Employee)

Endpoints available for standard employees.

POST /api/register

Description: Register a new user account.

Request Body:

{
    "name": "John Doe",
    "employee_code": "EMP12345",
    "email": "john.doe@example.com",
    "password": "password123",
    "password_confirmation": "password123",
    "department_id": 1,
    "manager_id": 2,
    "hire_date": "2023-01-15"
}

POST /api/login

Description: Login to get an authentication token.

Request Body:

{
    "identifier": "john.doe@example.com", // or "EMP12345"
    "password": "password123"
}

GET /api/user

Description: Fetch own user profile.

POST /api/leave-requests

Description: Submit a new leave request. The request starts in 'Draft' status.

Request Body:

{
    "leave_type_id": 1,
    "start_date": "2025-12-20",
    "end_date": "2025-12-22",
    "reason": "Holiday vacation"
}

GET /api/leave-requests

Description: View own leave request history.

PATCH /api/leave-requests/{leaveRequest}

Description: Update a leave request that is in 'Draft' status. To submit for approval, set current_status to 'Pending'.

Request Body (Example for submitting):

{
    "leave_type_id": 1,
    "start_date": "2025-12-20",
    "end_date": "2025-12-22",
    "reason": "Holiday vacation",
    "current_status": "Pending"
}

POST /api/logout

Description: Logout and invalidate the token.

Role: Approver (SPV, SL, ASMEN, TL, Manager)

Approvers have all Member permissions, plus the ability to approve or reject leave requests.

GET /api/leave-requests

Description: View pending leave requests that require their approval.

PATCH /api/leave-requests/{leaveRequest}/approve

Description: Approve or reject a leave request.

Request Body:

{
    "action": "Approved", // or "Rejected"
    "comments": "Enjoy your vacation!"
}

Role: Super Admin

The Super Admin has full access to the system for managing master data.

All endpoints are prefixed with /api/admin/master

GET /users

Description: Get a list of all users.

POST /users

Description: Create a new user and assign roles.

Request Body:

{
    "name": "Jane Doe",
    "employee_code": "EMP67890",
    "email": "jane.doe@example.com",
    "password": "password123",
    "department_id": 2,
    "manager_id": 1,
    "hire_date": "2024-02-01",
    "status": "Active",
    "roles": ["Employee", "Manager"]
}

GET /users/{user}

Description: Get details of a specific user, including their roles.

PUT/PATCH /users/{user}

Description: Update a user's information and roles. To change roles, provide the roles array. This will replace all existing roles with the new ones provided.

Request Body (Example):

{
    "name": "Jane Doe Updated",
    "roles": ["Employee"]
}

DELETE /users/{user}

Description: Delete a user.

Role Management

The roles attribute in the user creation and update endpoints accepts an array of role names. Providing this array will sync the user's roles, removing any they no longer have and adding new ones.

Available Roles:

  • Super Admin
  • SL
  • SPV
  • ASMEN
  • TL
  • Manager
  • Employee

CRUD: /departments, /leave-types, /public-holidays, /employee-entitlements, /leave-requests

These endpoints support full Create, Read, Update, and Delete operations. The required fields for creation/update generally correspond to the model's database columns.

For example, to create a department:

POST /departments

{
    "name": "Human Resources",
    "description": "HR Department"
}
